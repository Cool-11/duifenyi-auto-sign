## 一、v1.6 为什么重写

v1.5 及以前走的是**学生端网页接口**（`www.duifene.com/_CheckIn/CheckIn.ashx` 等）。
对分易改版后，这些接口对普通学生账号返回 `{"msg":"0","msgbox":"禁止访问！"}`，
于是：

- 签到码/汉字：列表里根本没有 `CheckInCode`，只能靠手动填；
- 二维码：取图接口拿不到教师端令牌；
- 定位：靠「距离预言机 + 三边测量」反推教室，用 5 km 探测环解 1000 km 外的
  目标时条件数极差（1 m 测距误差放大到 200 m 定位误差），解出来也签不上；
- 而「人数门禁」在人数接口异常时**永久静默等待**，四类签到会一起毫无反应。

**v1.6 改为使用官方 App 的 JSON 接口**（`https://dfapp.duifene.com`）。实测：
未登录访问返回 401、错误密码返回 `用户名或密码错误！`，接口全部在线。四类签到
所需的要素服务端都会直接下发：

| 类型 | 数据来源 | 提交 |
|---|---|---|
| 签到码 `type=1` | `GetModelByInProgress` 的 `checkIn.checkInCode` | `POST /CK/StudentCheckIn` |
| 二维码 `type=2` | 同上响应里的 `qrCode` 令牌 | `POST /CK/QrCodeCheckIn` |
| 定位 `type=3` | `checkIn.roomID` → `room/GetCheckInRoomById` 的经纬度 | `POST /CK/CheckInSignInLocation` |
| 汉字 `type=4` | `checkIn.checkInCode`（4 个汉字，顺序已正确） | `POST /CK/StudentCheckIn` |

顺带解决的老问题：不需要 Pillow/pyzbar（不再解码图片）、不需要微信链接登录、
不需要手动填签到码（服务端会下发，填了也能用）、挂机时 Token 自动续期。

## 二、快速上手（三分钟）

1. **双击 `对分易自动签到.exe`**（在 `dist/对分易自动签到/` 里）。
2. 输入**对分易账号（手机号/学号）和密码**，点「登录」。
   - 勾选「记住账号密码」后，下次开机会自动登录（密码用 Windows DPAPI 加密，只有本机能解）。
3. 右栏「监控课程」里选中要盯的课（多教学班时会显示「课程 · 班级」）。
4. 点「**开始监听**」。状态变「运行中」即开始每 3–5 秒检查一次。
5. 老师发起签到后会自动提交，右侧日志出现绿色「签到成功」。

> 只监控**当前选中的那一门课**。要多门课一起盯，请多开一个程序实例（各自选课）。

### 2.1 登录与凭证保存（持久化）

登录一次之后不用反复登录，保存分两层：

| 内容 | 存在哪里 | 有效期 | 说明 |
|---|---|---|---|
| Access Token | `duifenyi.ini` → `[APP_SESSION]` | 30 分钟，到期前 5 分钟自动续期 | 后台每 60 秒检查一次，挂机不断线 |
| Refresh Token | 同上 | 7 天 | 过期才需要重新登录 |
| 账号 + 密码 | `duifenyi.ini` → `[ACCOUNT]` | 长期 | **Windows DPAPI 按当前用户加密**，换机器/换账户解不开 |

启动顺序：先复用 `[APP_SESSION]` 里的令牌 → 令牌失效才用保存的密码自动登录一次
→ 都没有就停在登录界面。

- 取消勾选「记住账号密码」= 不保存密码；令牌仍会保存，所以 7 天内依旧免登录。
- 点「退出登录」会同时清掉令牌与保存的密码（下次必须重新输入）。
- 密码被改、或在别处把会话顶掉，会提示「登录状态已失效」，重登一次即可。
- `duifenyi.ini` **含凭证，不要外传或提交到仓库**（`.gitignore` 已排除）。

## 三、四类签到的实际行为

| 类型 | 自动完成 | 说明 |
|---|---|---|
| 签到码 | ✅ | 服务端下发 4 位码；若某次没下发，会持续重试，并提示可用「手动签到」兜底 |
| 二维码 | ✅ | 令牌随活动下发，每 5 秒取新一轮，滚动令牌过期就再取 |
| 定位 | ✅ | 取签到绑定教室的经纬度，按 3–18 米随机偏移提交，不必真的在教室 |
| 汉字 | ✅ | 服务端下发 4 个汉字（顺序即答案）；不下发时同样可手动兜底 |

**门禁（可在设置里调）**：

- `已签占比门槛`：默认 0.2，班里签够 20% 才跟签，避免「永远第一个签」；
- `门槛兜底时限`：默认 45 秒，超过后不管人数多少直接签——**保证不会因为等人数错过活动**；
- `小班人数阈值/等待时长`：总人数低于 5 人的班，创建满 5 秒就签；
- `检测后延迟秒数`：想再「稳一点」可设 5–10 秒；
- `监听时间窗`：默认 0–24 全天；设成 6–23 就只在白天轮询；
- 人数接口异常或人数为 0 时**直接放行**，不会像旧版那样卡死。

## 四、日志与排错

界面日志会同步写入 exe 同目录的 **`logs\run.log`**（超过 2 MB 轮转为 `run.log.1`），
启动崩溃也会带 traceback 记进去。**遇到问题先把这份日志取出来看。**

常见提示与含义：

| 日志 | 含义与处理 |
|---|---|
| `登录失败：用户名或密码错误！` | 密码错，或账号需要先在官网/App 上激活一次 |
| `登录状态已失效，请重新登录账号` | Refresh Token 过期（7 天）或被别处顶掉，重新登录 |
| `活动 xxx 未取到签到码，持续重试` | 服务端这次没下发码；把群里的 4 位码填进「手动签到」即可 |
| `活动 xxx 人数查询失败…跳过人数门槛直接签到` | 人数接口抖动，已自动放行，无需处理 |
| `活动 xxx 未取到教室坐标` | 这次签到没有绑定教室（老师用了「自由定位」），无法自动签 |
| `签到失败：<服务端原文>` | 原文即原因，例如「签到码错误」「签到已结束」 |
| `当前不在监听时间窗` | 设置里把时间窗改窄了 |

需要更细的排错（不想开界面）：命令行运行诊断脚本，逐环打印原始响应：

```bash
python diagnose_sign.py 20210001 你的密码
```

它只读不写：不会提交任何签到，只打印登录 / 课程 / 当前签到 / 人数 / 教室坐标。

## 五、参数说明

| 参数 | 默认 | 作用 |
|---|---|---|
| `poll_min_s` / `poll_max_s` | 3 / 5 | 轮询间隔随机区间（秒） |
| `error_backoff_max_s` | 60 | 连续异常时的退避上限（秒） |
| `monitor_start_hour` / `monitor_end_hour` | 0 / 24 | 监听时间窗（左闭右开） |
| `headcount_ratio` | 0.2 | 已签占比门槛，0 为不限制 |
| `headcount_deadline_s` | 45 | 门槛兜底时限（秒），超过即直接签 |
| `small_class_max` | 5 | 小班人数阈值 |
| `small_class_delay_s` | 5 | 小班活动创建后等待秒数 |
| `sign_delay_s` | 0 | 检测到签到后延迟多少秒再提交 |
| `stale_sign_minutes` | 30 | 创建超过多少分钟的活动不再处理 |
| `cooldown_seconds` | 15 | 命中限流后的静默时长（秒） |
| `proxy_url` | 空 | 留空=直连，且**忽略系统代理**（Clash「系统代理」不影响本程序）；填写如 `http://127.0.0.1:7890` 才会走代理，同时自动关闭 TLS 校验。启动日志第一屏会打印当前网络模式 |

内部常量（不暴露到界面）：二维码重试 5 秒/轮、定位重试 5 秒/轮、定位偏移 3–18 米、
手动签到内容 5 分钟有效。

## 六、源码运行与打包

```bash
pip install -r requirements.txt      # requests + pywebview
python main.py                       # 源码启动
python -m unittest discover -s tests # 76 项离线测试，不联网
python -m PyInstaller build.spec --noconfirm   # 产物：dist\对分易自动签到\
```

打包要点：`datas=[("web", "web")]` 必须带上界面资源；v1.6 已不再需要
Pillow/pyzbar，`build.spec` 里也把 `PIL`/`pyzbar`/`bs4` 显式排除了。
